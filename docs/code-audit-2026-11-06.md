# 代码质量、文档转换与磁盘清理审核

审核日期：2026-11-06（Asia/Taipei）。审核对象为当前工作区，包含原有未提交代码。本轮代码修正均由用户指定的 GPT-6.1 Sol 执行，主审负责复核、综合测试和浏览器验证。没有提交或回退原有工作区改动。

## 结论

原实现存在实际内容丢失、清理范围过宽、错误被隐藏及功能结果不真实等问题，已完成下表中的修正。PDF 转 Word 的代表性样本现在保留中文、图片、表内图片、合并单元格和表格顺序；这不构成对任意 PDF 的逐页、逐对象完全保真保证。

磁盘清理现有规则适合 macOS 用户级缓存、日志及明确选中的安装包。未执行实际用户目录清理；清理验证全部使用独立临时目录。界面报告的是已删除文件的逻辑体积，不等同于磁盘实际可用空间增加值。

## 已确认并修正的问题

## PDF→Word 完整性验证

使用本地真实 pdf2docx 引擎处理合成 PDF，并解包 DOCX 检查内容。没有用“文件非空”替代完整性断言。

| 样本 | 核验内容 | 结果 |
| --- | --- | --- |
| 目录、正文、PNG、合并表格、第二页 | 图片存在、`gridSpan` 存在、表格仍位于前后正文之间、两页文字保留 | 通过 |
| 上述 PDF 仅选择第 2 页 | 第 2 页正文存在，第 1 页正文不出现 | 通过 |
| 纯扫描图片页 | 不允许空白 DOCX 假成功；成功时含实际图片 | 通过，保留图像，不提供 OCR |
| 两页中文、多图、表内图片和合并表格 | 两页中文存在、3 张图片保留、表内 drawing 存在、合并单元格存在 | 通过 |
| 错误页码与已有输出 | 错误请求不产生输出/暂存遗留，原输出保持原字节 | 通过 |

这里验证的是代表性文档的内容和结构。PDF 通常不包含 Word 的表格、章节或页眉语义，因此复杂无框线表格、公式、矢量图、剪裁、字体替代及多栏版面仍可能需要人工检查。当前自动检查能发现整个结果空白或整体文字/图片缺失，不能证明每个对象都完整。

## 清理效果和性能

测试构造 100 个子目录、10,000 个 7 字节文件，使用 debug 构建，不含准备 fixture 的时间。修复测试隔离后连续 5 次：

| 操作 | 范围 |
| --- | --- |
| 扫描 10,000 文件 | 36.52–38.20 ms |
| 逐项安全检查并删除 | 820.56–1300.30 ms |
| 删除后断言 | 10,000 文件全部计入，逻辑体积 70,000 字节，规则根目录保留 |

该测量只代表本机临时小文件，不是实际用户缓存、百万文件或磁盘碎片条件下的性能承诺。扫描本身与目录遍历量线性相关；删除还包含逐祖先路径检查。没有为速度放宽清理边界。

稀疏文件、硬链接、APFS 克隆/快照、仍被进程打开的文件均可能使逻辑删除体积与磁盘净释放量不同。现有路径式文件操作也不能原子防御外部恶意进程在校验后替换目录；应用内部互斥不等于跨进程文件系统沙箱。

## 尚未覆盖的验收边界

- 没有建立真实业务 PDF 大样本库，也没有逐页渲染前后像素对比。不能将以上样本通过解释为任意文档 100% 保真。
- OCR 未实现。扫描件中的表格与文字可能以图片保留，不能据此宣称可编辑。
- LibreOffice、Microsoft Word、Pages 和 Windows 的原生流程没有在本轮逐一端到端验收；外部引擎安装与版本差异仍影响可用性。转换引擎超时会结束直接子进程，不主动关闭用户 Office 应用。
- macOS 清理规则是静态路径清单；聊天应用新版目录、浏览器其他 profile、其他磁盘/其他操作系统及实际授权状态未在用户数据上验证。扫描不到不等于不存在缓存；无法读取不再被当成完整扫描。
- 前端的大文档内存峰值、长时间阅读、冷启动和真实 Tauri 窗口响应尚未做系统性能剖析。本轮已修复同步耗时命令的执行位置，但没有宣称完成全产品性能认证。
